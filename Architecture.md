# WalkingLab Architecture

## Overview
The system uses a decoupled architecture to isolate the Python backend (inference, few-shot learning, filtering, metrics) from the frontend (NiceGUI / Vue 3 browser client). The backend processes video data to extract keypoints, executes on-demand few-shot fine-tuning, smooths trajectories, and calculates metrics. The frontend serves as the interactive client that plays videos locally, renders skeleton overlays on HTML5 Canvas/SVG, maintains and archives the Ground-Truth (GT) Annotation Session (`Save Session (.zip)` / `Load Session (.zip)`) **100% in browser memory**, and sends the compressed session `.zip` to the backend **only** when few-shot training is requested.

## Modules

### 0. Package Root (`walkinglab`)
- **__init__.py**: Performs platform initialization. On Windows (`win32`), registers the virtual environment's root (`sys.prefix`) and `Scripts` directory via `os.add_dll_directory` and `PATH` so bundled `msvc-runtime` DLLs (`msvcp140.dll`, `vcruntime140.dll`, etc.) are resolved by OpenVINO (`_pyopenvino`) and PyTorch (`c10.dll`) even when launched through `uv`'s wrapper executable.

### 1. UI Package (`walkinglab.ui`)
Built with NiceGUI, leveraging Vue 3 custom components for high-performance video overlays and client-side session management.
- **app.py**: Main entry point for the NiceGUI app, manages tabs and API routes (e.g. `/api/upload_video`).
- **annotation.py**: Unified Annotation & Few-Shot Learning workspace driven by `AnnotationController`:
  - **Top Workflow Bar (3 Guided Cards)**:
    1. **1. Model Weights**: Displays active weights (`Default: yolo26s-pose.pt` or custom uploaded `.pt`), allows uploading pre-existing trained `.pt` weights or resetting to default weights via the `@property` `controller.active_weights_path` (`inference.config.active_weights_path`) without eagerly loading the model upfront.
    2. **2. Annotation Session**: Displays saved GT frame count (`Session: N GT Frames`), triggers 100% browser-side **Load Session (`.zip`)** (`tracker.open_session_dialog`) and **Save Session (`.zip`)** (`tracker.save_session_zip`), and opens videos (`tracker.open_file_dialog`).
    3. **3. Few-Shot Learning**: When **Train Few-Shot Model** is clicked, calls `tracker.request_session_zip_for_training()` so the browser builds the compressed session `.zip` and emits `training_zip_ready` (`zip_b64`), which Python dispatches to `training.run_few_shot_training` via `run.cpu_bound`. Provides a collapsible **Advanced Settings** toggle (`Epochs`, `Learning Rate`, `Freeze Layers`) with guided defaults (`10`, `0.001`, `10`), and exposes **Save New Weights (`.pt`)** and **Use Trained** actions upon completion.
  - **Center Transport & Session Bar**: Provides video frame-stepping (`Prev (-1)`, `Play / Pause`, `Next (+1)`), **Save Frame to Session (GT)** (`save_current_frame_to_session`), and saved session navigation (`<`, `Saved i/N`, `>`, `Delete GT`).
  - **Right Sidebar (17-Keypoint Inspector + Session Frame Action Box)**: Renders all 17 COCO keypoints with their unique color swatches, frame-level status badges (`set`, `occluded`, `unset`), canvas overlay visibility toggles (`visibility` / `visibility_off`), active keypoint selection (`edit`), and per-frame occlusion/deletion controls. At the bottom of the inspector, a dedicated **Session Frame Action Box** displays whether the current frame is saved in the session (`current_frame_session_status`), a full-width **Save Current Frame to Session (GT)** button, and quick `Prev GT` / `Next GT` / `Back to Video` navigation buttons.
- **pose.py**: Visualizer for the extracted pose keypoints over video frames.
- **settings.py**: Controls for loading videos, connecting cameras, and tuning filter hyperparameters.
- **metrics.py**: Dashboard for longitudinal trend analysis and kinematic curves.
- **components/video_tracker.py & components/video_tracker.js**: Custom Vue 3 component (`VideoTracker`) that orchestrates live webcam streaming, HTTP video file uploads, interactive SVG keypoint annotation, and the **100% frontend-owned Annotation Session**:
  - **Frontend Session, Filmstrip & Browser-Native ZIP Archiver (`sessionSamples`)**: Stores saved GT frames (`{sample_id, video_name, frame_index, image_b64, markers}`) exclusively in browser memory across multiple loaded videos (emitting only lightweight count/index metadata in `session_updated` without transferring images to the server). Includes a pure-JS PKZIP builder (`buildSessionZipUint8Array`, `save_session_zip`) and parser (`parseZipArchive`, `handleSessionZipUpload`) so saving and loading `.zip` sessions happen **entirely in the browser without backend round-trips**. Only when `request_session_zip_for_training()` is invoked does the browser package `this.sessionSamples` into a `.zip` and emit `training_zip_ready` (`zip_b64`) to the backend.
  - **Color-Coded 17-Keypoint & Anatomical Skeleton Overlay**: Renders all 17 COCO keypoints (`id: 0..16`) using their distinct categorical hex colors (`keypointColors`) and 16 anatomical bone connections (`skeletonEdges`), styling occluded keypoints (`visibility === 0`) with dashed rings and reduced opacity.
  - **Interactive Annotation Editing & Visibility Filtering**: Supports zero-latency client-side drag-and-drop on any SVG marker as well as click-to-place when a keypoint is selected (`activeKeypointId`), automatically pausing video playback, converting pointer coordinates via `calculateVideoBounds` into normalized `[0, 1]` coordinates, updating `all_frames_markers[frameIndex]` (or `sessionSamples[activeSessionIndex].markers`), and emitting lightweight `annotation_updated`, `session_updated`, and `frame_changed` events back to Python.
  - **Real-Time Webcam Buffer**: Maintains a tunable **200 ms delayed frame buffer** rendered onto `<canvas ref="displayCanvas">`, assigns a sequential `frame_index` to every captured frame, dilates inference dispatch (default `1` in `4` frames), interpolates marker coordinates across intermediate frames, and dynamically expands the buffer delay if backend inference latency exceeds half the buffer duration.

### 2. Backend Package (`walkinglab.backend`)
Handles data processing, model inference, and decoupled few-shot training. Exposes data (e.g., JSON coordinates and `.pt` byte streams) rather than rendered frames, and never retains uploaded video files or session images during annotation.
- **keypoints.py**: Defines the canonical 17 COCO pose keypoints (`COCO_KEYPOINTS`, `KEYPOINT_BY_ID`, `KEYPOINT_COLORS`, `KEYPOINT_NAMES`) with 17 unique categorical hex colors, the 16 anatomical skeleton bone connections (`SKELETON_EDGES`), `get_keypoint_color`, `format_annotations_for_export`, and Ultralytics YOLO-Pose training dataset builders (`format_frame_yolo_pose_label`, `generate_yolo_pose_data_yaml`, `build_yolo_pose_dataset_zip`).
- **training.py**: Dedicated, strictly isolated module for compressed session management and few-shot YOLO-Pose fine-tuning (**never imports `inference.py` and never loads any model upfront at import time**):
  - `pack_session_to_zip` & `unpack_session_from_zip` & `parse_frame_yolo_pose_label`: Utilities for packing/unpacking YOLO-Pose session `.zip` archives (`session.json`, `data.yaml`, `annotations.json`, `images/train/*.jpg`, and `labels/train/*.txt`).
  - `run_few_shot_training`: Unpacks the compressed session `.zip` sent from the frontend into an isolated temporary workspace, lazily instantiates `ultralytics.YOLO(base_weights_path)` strictly inside the worker call, runs `.train(data=..., epochs=..., lr0=..., freeze=..., imgsz=..., batch=...)`, and returns the resulting fine-tuned `.pt` weights bytes (`weights_bytes`).
- **inference.py**: Handles OpenVINO CPU-accelerated model execution (`YOLO-Pose`), sharing a single base `ov.Model`, preprocessor (`preprocess`), and postprocessor (`postprocess` — outputting normalized `{"id": int, "x": float, "y": float}` keypoints) across two dedicated, statically-shaped compilation pipelines (`_compile_pipeline`). Manages active model weights lazily via `InferenceConfig.active_weights_path` (`@property` getter/setter on `inference.config.active_weights_path` and `PoseEstimator.weights_path`, resetting `estimator = None` without upfront loading until `get_estimator()` is called by an inference request):
  - **Live Webcam (`realtime_compiled_model` / `infer` / `predict` / `process_frame`)**: Compiled eagerly with static input shape `[1, 3, 640, 640]` (`REALTIME_BATCH_SIZE = 1`) and `ov.properties.hint.PerformanceMode.LATENCY`.
  - **Video File (`batch_compiled_model` / `process_video_file`)**: Compiled lazily with static input shape `[4, 3, 640, 640]` (`BATCH_SIZE = 4`) and `ov.properties.hint.PerformanceMode.THROUGHPUT`, executed asynchronously via `ov.AsyncInferQueue`.
- **filtering.py**: Implements NumPy-based (`np.interp`) real-time frame interpolation (`interpolate_frame_sequence`) and the stateful `RealtimeFrameBufferInterpolator`.
- **analysis.py**: Calculates spatiotemporal parameters (stride, cadence) and kinematic curves from the smoothed trajectories.

## Data Flow
The system supports two real-time/batch inference pipelines plus a 100% frontend-owned Annotation Session & on-demand Few-Shot Learning loop:

### A. Live Webcam Pipeline (Buffered & Interpolated)
1. Frontend captures camera frames at native FPS into a FIFO `frameBuffer` with a monotonically increasing `frame_index` and timestamp.
2. Frontend dilates inference requests (`frameDilation = 4` by default), emitting `frame_ready` (`{ frame_index, frame_data }`) over NiceGUI WebSockets only on dilated keyframes while the worker is free.
3. Backend `process_frame` decodes the frame, runs synchronous `B=1` `LATENCY` inference, and passes `(frame_index, markers, inference_time_ms)` to `RealtimeFrameBufferInterpolator.record_inference`.
4. Backend interpolates all intermediate frames `[prev_frame_index .. frame_index]` and returns the indexed payload.
5. Frontend `displayCanvas` renders buffered video frames delayed by `bufferDelayMs` (`200 ms` default) and overlays the exact frame-synchronized markers on the SVG layer.

### B. File Upload Batch Pipeline
1. Frontend creates a local browser blob URL (`URL.createObjectURL(file)`) for `<video>` playback, calculates exact duration, and asks backend for an empirical ETA estimate (`/api/estimate`).
2. Video is uploaded to the backend via `XMLHttpRequest` (`POST /api/upload_video`).
3. Backend streams the MP4 into a `NamedTemporaryFile(suffix=".mp4", delete_on_close=False)` context block (`shutil.copyfileobj` + `temp_video.close()`), runs batched `AsyncInferQueue` (`B=4`) inference inside the `with` block using `inference.config.active_weights_path`, and automatically deletes the temporary video file upon exiting the `with` block.
4. JSON coordinates (`all_frames_markers`) are returned to the browser and synced chronologically to the HTML5 `<video>` playback.

### C. Frontend Annotation Session & On-Demand Few-Shot Learning Loop
1. **Model Weights Selection**: User selects Default Weights (`yolo26s-pose.pt`) or uploads pre-existing `.pt` weights. Setting `controller.active_weights_path = path` (`inference.config.active_weights_path`) updates the path lazily without loading the model upfront.
2. **Load Session (Optional, 100% Frontend)**: User clicks **Load Session (`.zip`)** (`open_session_dialog`); `video_tracker.js` parses the `.zip` archive directly in the browser (`parseZipArchive`) and restores `this.sessionSamples` (`image_b64` + `markers`) without calling the backend.
3. **Multi-Video Frame Selection & GT Creation (100% Frontend)**: User loads one or more videos, scrubs/steps to target frames, refines keypoints on the interactive 17-color SVG overlay, and clicks **Save Current Frame to Session (GT)**. The browser captures the clean frame (`image_b64`) directly from the HTML5 `<video>` element onto `<canvas>` along with the frame's GT `markers`, stores them in `this.sessionSamples` in browser memory, and adds a thumbnail card to the bottom **Session GT Filmstrip**. Only lightweight count/index metadata is emitted in `session_updated`.
4. **Browse & Toggle Session GT (100% Frontend)**: User clicks thumbnails in the filmstrip or `Prev GT` / `Next GT` to toggle through all saved session frames in `'session'` review mode, rendering `sample.image_b64` and `sample.markers` directly in the browser.
5. **Save Compressed Session (100% Frontend)**: Clicking **Save Session (`.zip`)** invokes `save_session_zip()` in `video_tracker.js`, which builds the `.zip` archive (`session.json`, `data.yaml`, `annotations.json`, `images/train/*.jpg`, `labels/train/*.txt`) directly in the browser (`buildSessionZipUint8Array`) and triggers a browser `<a download>` without touching the backend.
6. **Few-Shot Learning & New Weights Export (On-Demand Backend Worker)**: Clicking **Train Few-Shot Model** calls `tracker.request_session_zip_for_training()`. The browser builds the compressed session `.zip` and emits `training_zip_ready` (`zip_b64`) to the backend, which passes the `.zip` bytes and selected weights path to `training.run_few_shot_training`. Inside the worker, `YOLO(base_weights_path)` is lazily loaded, fine-tuned on the extracted session dataset, and the resulting `.pt` weights bytes are returned so the user can click **Save New Weights (`.pt`)** or **Use Trained**.
